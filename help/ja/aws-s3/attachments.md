# Amazon S3 の添付ファイル

Redmine Kit AWS S3 は、環境変数 `REDMINE_S3_BUCKET` を設定すると、Redmine の添付ファイルを Amazon S3 のバケットに保存します。設定しなければ、添付ファイルはローカルディスクのままです。ブラウザーは、Redmine の CloudFront ディストリビューションを通してファイルを S3 に直接アップロードし、Redmine がいつもどおりユーザーの権限を確認したあと、同じドメインの署名付き URL からダウンロードします。ユーザーは、これまでどおり添付ファイルを追加し、開きます。

## ファイルのアップロード

ファイルを添付するフォームは、進捗バーを含めて Redmine と同じように動きます。GuardDuty マルウェアスキャン (`REDMINE_S3_MALWARE_SCAN`) が有効なときは、スキャンで脅威が見つからなかったファイルだけを登録します。

- スキャンが完了するまで、フォームは待って問い合わせ直します。しばらくすると「ファイルのマルウェアスキャンが完了していません。しばらくしてからもう一度試してください。」と表示します。
- 脅威のあるファイルは削除してブロックします:「マルウェアスキャンで脅威を検出したため、ファイルをブロックしました。」
- スキャンが完了しなかったファイルもブロックします:「マルウェアスキャンが完了しなかったため、ファイルをブロックしました (…)。」

## S3 タブ

「管理」›「AWS」›「S3」に、プラグインの設定の状態を表示します。開けるのはシステム管理者だけです。AWS を呼ぶのは、タブのリンクをクリックしたときだけで、その操作は Redmine のログに書きます。

- 「環境変数」: 「バケット」、「リージョン」、「CloudFront ドメイン」、「CloudFront キーペア ID」、「CloudFront 秘密鍵」(「設定済み」か「未設定」だけ)、「GuardDuty マルウェアスキャン」、「ローカルキャッシュ」です。それぞれ、値の元の環境変数を添えます。
- 「接続テスト」: 「読み書きテスト」は、バケットにテスト用のオブジェクトを書き込み、読み込み、削除します。「配信テスト」は、テスト用のオブジェクトを署名付き URL で CloudFront から取得し、署名なしの URL が拒否されることを確認します。失敗した呼び出しは、エラーのクラスだけを表示します。
- 「マルウェアスキャンでブロックしたファイル」: ブロックした最近の 20 個のファイルを、「日時」、「スキャン結果」、ファイル名、「ユーザー」とともに表示します。
- 「整合性チェック」: 「整合性チェックを実行」で、データベースの添付ファイルとバケットのオブジェクトをバックグラウンドのジョブで比べ、「添付ファイル数」、「S3 オブジェクト数」、「S3 にないファイル」、「未使用のオブジェクト」を表示します。
- 「設定」: 「ダウンロード URL の有効期限」と「アップロード URL の有効期限」(秒)、「キャッシュサイズの上限」(MB) です。正の整数で入力し、「保存」で保存します。

バケットを設定していないときは、警告と、環境変数と設定だけを表示します。「管理」›「プラグイン」で Redmine Kit AWS S3 の「設定」を開くと、このタブを開きます。
